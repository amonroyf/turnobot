# BUG-002 — El harness de tests crashea al comparar documentos con arrays

- **Severidad:** media
- **Prioridad:** alta (bloquea la evidencia de QA)
- **Entorno:** local (emulador) / GCP
- **Estado:** ✅ RESUELTO en `48ff6d4` (16 nov 2026)
- **Descubierto por:** lectura del código fuente + reproducción aislada

## Pasos para reproducir (antes del fix)

1. `turnobot-test-learn/sandbox/delta.go` → función `equalDocs`:

   ```go
   func equalDocs(a, b interface{}) bool {
       am, oka := a.(map[string]interface{})
       bm, okb := b.(map[string]interface{})
       if !oka || !okb {
           return a == b          // <-- panic con tipos no comparables
       }
       ...
   }
   ```

2. Un documento de Firestore tiene un campo array. En Turnobot son varios:
   `empleados.{slug}.horario.{dia}.turnos[]`, `servicios_ids[]`,
   `reservas.participantes[]`.
3. Cuando `Delta()` compara un documento **modificado** (no agregado) que tiene
   un array, entra a `equalDocs` → `a == b` sobre dos `[]interface{}`.

## Esperado

`Delta()` devuelve el diff de los documentos modificados, sin crashear.

## Actual

```
panic: runtime error: comparing uncomparable type []interface {}
```

El panic ocurre **dentro del test**, en `sandbox.Intercept`, y aborta el test
completo. No es un fallo de aserción: es un fallo de la herramienta.

## Reproducción aislada

Copié la función a un módulo aparte con un doc que tiene un array:

```
$ go test -run TestPanicaConSlice -v
=== RUN   TestPanicaConSlice
PANIC CONFIRMADO: runtime error: comparing uncomparable type []interface {}
--- PASS: TestPanicaConSlice (0.00s)
```

## Causa raíz

`a == b` en Go compara interfaces por identidad de tipo y valor, y **no
admite tipos no comparables** (slices, maps, funciones). El autor当面 del
comentario lo sabía ("comparación simple por serialización no disponible sin
encoding") y usó el operador `==` como atajo. Faltaba el caso de los slices.

## Impacto

- **A quién afecta:** a cualquiera que use el harness para comparar un doc
  modificado con arrays. Es el caso más común: `empleados` con horario.
- **Cuánto:** el harness solo se usaba en `backend/paginacion_test.go` (4
  tests), y esos testsreservation solo **agregan** reservas, nunca modifican
  un doc con arrays. Por eso el bug estaba latente: **nadie había tocado el
  camino que lo dispara.**
- **Gravedad real:** el bug estaba en la herramienta de evidencia, no en el
  producto. Pero si el harness crashea justo cuando hay algo interesante que
  reportar, el harness deja de ser confiable.

## Nota

¿Reproducible? **Siempre**, si un doc modificado contiene un array.

## Fix aplicado

```go
func equalDocs(a, b interface{}) bool {
    return reflect.DeepEqual(a, b)
}
```

`reflect.DeepEqual` maneja maps, slices, punteros y escalares sin panic, y
compara `time.Time` correctamente (los docs de Firestore los traen como
`time.Time`, no como string).

## Lección

Un bug en la **herramienta de prueba** es más peligroso que uno en el producto:
no lo nota nadie hasta que necesita la herramienta. Y "funciona en los tests
que lo usan" no es "funciona" — el código no ejercitado es el que tiene bugs.
