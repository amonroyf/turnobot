# BUG-001 — `scripts/run-qa.sh` fallaba siempre: llamaba a un script npm inexistente

- **Severidad:** alta
- **Prioridad:** alta
- **Entorno:** local / CI
- **Estado:** ✅ RESUELTO en `d434434` (14 nov 2026)
- **Descubierto por:** lectura del código fuente (`docs/PLAN_QA.md` §1.1, ítem 1)

## Pasos para reproducir (antes del fix)

1. `cd frontend`
2. `npm run test`
3. npm responde: `npm error Missing script: "test"`

Y el efecto real, que es el que importa:

1. `cd /ruta/al/repo`
2. `./scripts/run-qa.sh`
3. El script muere en la **primera capa** (Frontend / Vitest) con exit code != 0.
   Nunca llega a correr E2E ni a calcular la cobertura.

## Esperado

`./scripts/run-qa.sh` corre las tres capas (Go → Vitest → Playwright) y falla
solo si un test falla de verdad.

## Actual

`scripts/run-qa.sh` llamaba `npm run test`, pero `frontend/package.json` no
tenía el script `test`. El runner de QA completo era **inutilizable**: fallaba
siempre, y por un motivo que no tenía nada que ver con la calidad del código.

## Causa raíz

El script `run-qa.sh` y el `package.json` se escribieron en momentos distintos
y nadie ejecutó el runner de punta a punta antes de commitearlo. El
`package.json` sí tenía `test:unit` (mismo contenido, otro nombre), o sea que
el alias correcto ya existía con otro nombre.

## Evidencia

```bash
$ git show d434434 -- frontend/package.json
+    "test": "vitest run",

$ git show d434434 -- scripts/run-qa.sh
+echo "=== Frontend (Vitest) ==="
+npm run test
```

## Impacto

- **A quién afecta:** a quien intentara correr la suite QA completa. El script
  moría en la capa 2 de 3, sin llegar a las E2E.
- **Cuánto:** bloqueaba por completo el runner local. El CI tampoco lo detectó
  porque el workflow de GitHub Actions invoca `vitest` directamente, no el
  script.
- **Gravedad real:** baja para el producto, alta para el proceso. Es
  exactamente el tipo de bug que hace perder una mañana: el mensaje de error
  (`Missing script: "test"`) no dice nada sobre qué pasa.

## Nota

¿Reproducible? **Siempre**, en cualquier máquina, sin condiciones.

## Lección (lo que le dejo al proyecto)

Un runner que ejecuta varias capas necesita **una prueba que lo ejecute de
punta a punta**. Hoy `run-qa.sh` existe pero nadie lo corría. El plan de QA
debería incluir, como entregable de la semana 1, una corrida completa del
runner — no de las capas sueltas.
